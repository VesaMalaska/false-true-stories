# False True Stories — Runtime Packet Specification

## Purpose

Define the compact derived execution representation used during live storytelling.

> Compile relevant rules and truth before the performance. Do not reinterpret the whole framework for every continuation.

## Authority

The Runtime Packet is derived and disposable, never canon and never more authoritative than framework rules, explicit corrections, World Seed, established run history/state, saved environment/profile, and other authoritative Story Pack material.

If conflict occurs, authority wins and the packet is refreshed. Losing a packet must not mean losing canon.

## Preparation mode

Preparation may read framework sources, validate pack/run selection, reconcile environment/persistence, load seed/state/history/supporting material, resolve the Story Run Profile, identify active continuity, and build or refresh the packet.

## Live Runtime Mode

Ordinary narration should operate primarily from the Runtime Packet, current scene/recent conversation, and uncheckpointed runtime deltas.

The runtime MUST NOT repeatedly redo setup-time validation or reread the complete framework merely because the user says “continue”.

## Packet contents

Preserve applicable semantics: pack/run identity, freshness references, effective profile, protagonist essentials, active scene/location/situation, important active characters and relevant knowledge/goals/conditions/relationships, active goals/plans/threats/opportunities/promises/unresolved threads, relevant possessions/constraints/conditions, immediate protected mysteries or narrator constraints, tone/boundaries/reality/narrator freedom, recent consequential events, pending deltas, and checkpoint status.

Keep only what near-term narration needs.

## Runtime-essential vs reference/on-demand

Near-term relevant material belongs in the packet. Dormant lore, distant characters, resolved threads, old history, and already-compiled procedures may remain reference/on-demand until relevant.

## Runtime deltas

Newly important truth may first be captured as concise deltas rather than rebuilding all continuity records after every response.

## Checkpoints

Consolidate relevant deltas into authoritative state/history at natural checkpoints. Not every meaningful event requires an immediate blocking save. Mandatory protocol persistence rules still apply.

## Escalation

Consult authority when contradictions appear, dormant seed facts become relevant, requested history is absent from active context, continuity confidence is low, a mystery/boundary cannot be resolved safely, recovery/handoff requires reconstruction, or a new arc activates dormant material. Refresh the packet and return to Live Runtime Mode.

## Performance principles

FTS cannot guarantee provider response time, but ordinary continuation should avoid unnecessary full-framework rereads, repeated setup validation, unchanged record rewrites, and optional configuration questions when defaults/current settings are valid.

Responsiveness is part of the listening experience.

## Privacy and portability

Packet representations may contain narrator-only truth and must follow private-material handling. “Runtime Packet” is semantic, not a required filename; structured context, internal notes, temporary files, or compiled prompt sections are valid equivalents.

> Move complexity out of storytelling time.
